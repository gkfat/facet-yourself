## UC-001 以 Google 登入

- **Actor**：CTX-ACTOR-001
- **對應 Story**：STORY-001
- **對應 Requirement**：FR-001, FR-032

**Preconditions**

- 使用者未登入（含訪客）
- Firebase Auth 已啟用 Google provider

**Main Flow**

1. 使用者在 app 中選擇 Google 登入
2. 系統開啟 Google 登入視窗
3. 使用者完成 Google 授權
4. 前端取得 Firebase ID token 並送交後端 〔NFR-003〕
5. 後端驗證 ID token 並辨識帳號 〔NFR-001, NFR-003〕
6. 系統回傳登入成功並導向原頁面

**Alternate Flows**

- **使用者關閉或取消登入視窗**：保持訪客狀態並提示可再次登入
- **ID token 無效或過期**：後端回傳 401，前端重新取得 token 重試一次，仍失敗則提示重新登入
- **Google 或 Firebase Auth 服務失敗**：顯示明確錯誤，保持訪客狀態，不寫入任何資料

**Postconditions**

- 使用者已登入，後端可辨識其帳號
- 首次登入者另走 UC-002

## UC-002 首次登入建立帳號並領取贈點

- **Actor**：CTX-ACTOR-001
- **對應 Story**：STORY-002
- **對應 Requirement**：FR-001, FR-037

**Preconditions**

- 使用者首次以此 Google 帳號登入（後端查無對應帳號）

**Main Flow**

1. 後端驗證 ID token 後確認帳號不存在
2. 系統建立使用者帳號與點數帳戶 〔NFR-017〕
3. 系統檢查贈點紀錄（上次贈點未滿 3 個月者不發放），並一次性發放 3 點贈點、記錄贈點時間與異動 〔NFR-017〕
4. 系統告知使用者已獲得 3 點

**Alternate Flows**

- **並行或重送的首次登入請求**：贈點 MUST 僅發放一次，其餘請求回傳既有帳號
- **建立帳號或點數帳戶失敗**：整體回滾、不發放贈點，回傳明確錯誤，使用者可重試
- **帳號已存在**：略過贈點，視為一般登入
- **此 Google 帳號先前曾刪除帳號**：視為全新帳號：建立新的使用者與點數帳戶，不繼承任何歷史紀錄；若上次贈點未滿 3 個月則不再發放贈點（RULE-031）

**Postconditions**

- 帳號與點數帳戶存在，餘額 3 點，贈點僅一次

> 備註：贈點效期見 FR-042（長度待討論）

## UC-003 填寫生日、星座與選填資料

- **Actor**：CTX-ACTOR-001
- **對應 Story**：STORY-003
- **對應 Requirement**：FR-002

**Preconditions**

- 使用者開啟個人資料或測驗入口

**Main Flow**

1. 使用者輸入生日；系統帶入對應星座供確認 〔NFR-001〕
2. 使用者可選填血型（A/B/O/AB/不知道）
3. 使用者可選填 MBTI、出生時間與出生地點（出生地點從預設城市清單選擇）
4. 系統驗證必填欄位（生日、星座）並在後端驗證格式 〔NFR-001〕
5. 已登入者：系統儲存資料；訪客：以 session id 暫存於 Firestore，TTL 1 天，不與帳號關聯 〔NFR-005〕

**Alternate Flows**

- **必填欄位缺漏或格式無效**：標示錯誤並阻擋繼續
- **血型選「不知道」**：記錄為未知，後續分析不計入血型
- **訪客**：畫面明確提示未登入將不保留資料

**Postconditions**

- 個人資料可供單項結果、summary 與人類圖使用

> 備註：訪客資料不寫入 Firestore（FR-032）

## UC-004 取得單項免費結果（星座、血型）

- **Actor**：CTX-ACTOR-001
- **對應 Story**：STORY-004
- **對應 Requirement**：FR-040, FR-007, FR-002

**Preconditions**

- 已提供生日／星座，血型分析另需已選血型

**Main Flow**

1. 使用者選擇查看星座結果
2. 後端依生日／星座回傳固定結果內容 〔NFR-010, NFR-007〕
3. 使用者可選擇查看血型分析，後端回傳該血型固定內容
4. 系統顯示結果並附娛樂性免責說明 〔NFR-007〕

**Alternate Flows**

- **血型為「不知道」或未填**：不提供血型分析，提示可補填
- **結果內容讀取失敗**：回傳明確錯誤，不使用 AI 補足 〔NFR-011〕

**Postconditions**

- 使用者看到固定單項結果；系統不扣點、不儲存此結果

## UC-005 完成 MBTI 測驗

- **Actor**：CTX-ACTOR-001
- **對應 Story**：STORY-005
- **對應 Requirement**：FR-003, FR-004, FR-024, FR-040, FR-007

**Preconditions**

- 使用者開啟測驗清單

**Main Flow**

1. 系統顯示可用測驗清單，使用者選擇 MBTI 〔NFR-012〕
2. 後端回傳含版本的題目與選項
3. 使用者逐題作答；已告知時才記錄作答時間 〔NFR-005〕
4. 使用者送出作答，後端驗證並依評分規則計算 16 型 〔NFR-001〕
5. 系統顯示 MBTI 固定結果與免責說明 〔NFR-007〕
6. 已登入者：系統保存此次測驗版本、作答與結果；訪客：以 session id 暫存於 Firestore，TTL 1 天 〔NFR-005〕

**Alternate Flows**

- **作答不完整或選項無效**：後端拒絕並指出缺漏題目
- **測驗版本已更新**：以送出時的版本評分，記錄所用版本
- **訪客**：結果頁提示未登入將不保留，並提供登入入口（UC-006）
- **保存失敗**：仍顯示結果，提示保存失敗並可重試

**Postconditions**

- 使用者取得 MBTI 結果；登入者的測驗結果保存 3 個月

## UC-006 訪客登入並保存當次結果

- **Actor**：CTX-ACTOR-001
- **對應 Story**：STORY-006
- **對應 Requirement**：FR-032, FR-005, FR-001

**Preconditions**

- 訪客已完成測驗並看到結果
- 結果已以 session id 暫存於 Firestore（TTL 1 天）

**Main Flow**

1. 結果頁提示未登入將不保留，使用者選擇登入保存
2. 使用者完成 UC-001 登入
3. 後端依 session id 取出暫存結果並寫入該帳號 〔NFR-001, NFR-003〕
4. 系統確認已保存並顯示於個人中心

**Alternate Flows**

- **使用者拒絕登入**：不保存，暫存結果於 TTL 到期後自動清除
- **暫存結果已過期（超過 1 天）或 session 不存在**：提示結果已失效，引導重新測驗
- **登入後寫入失敗**：提示失敗並保留畫面結果供重試
- **重送造成重複寫入**：以當次結果冪等寫入，不產生重複紀錄

**Postconditions**

- 當次結果歸屬登入帳號，保存 3 個月；該 session 的暫存結果已清除

> 備註：暫存機制已定：session id + Firestore TTL 1 天（FR-032）

## UC-007 取得多維度分析報告（已廢止，由 UC-054 取代）

- **Actor**：CTX-ACTOR-001
- **對應 Story**：STORY-007
- **對應 Requirement**：FR-006, FR-007, FR-038, FR-041, FR-014, FR-042, FR-032, FR-040

**Preconditions**

- 使用者已登入
- 已提供星座與 MBTI（血型選填）

**Main Flow**

1. 使用者選擇取得多維度分析報告
2. 後端驗證登入身分 〔NFR-003〕
3. 後端依有無血型決定組合：星座+MBTI 或 星座+MBTI+血型（血型未知則用前者）
4. 後端檢查該會員是否已生成過此組合；若已生成則直接回傳已存 summary，不扣點 〔NFR-017〕
5. 否則後端檢查未過期點數餘額 ≥ 1 〔NFR-017〕
6. 後端原子地扣 1 點、記錄異動並保存該 summary 結果 〔NFR-017〕
7. 系統顯示 summary 與免責說明 〔NFR-007, NFR-010〕

**Alternate Flows**

- **訪客**：不可取得；提示登入（UC-001）
- **缺少 MBTI**：不提供 summary，引導完成 MBTI 或改看單項結果
- **點數不足或已過期**：拒絕並引導購買點數（UC-010）
- **並行重複請求**：僅扣一次點，其餘回傳已生成結果
- **讀取組合內容失敗**：不扣點，回傳明確錯誤 〔NFR-011〕

- **對應 Requirement**：FR-085, FR-086, NFR-031, NFR-032

**Preconditions**

- 使用者已登入
- 至少選擇一個穩定特質系統（含自我分析），且每個所選系統都有所需資料（自我分析須有未到期的結果）
- 點數足夠

**Main Flow**

1. 使用者在「綜合分析」頁選一個以上、互不相同的系統，可選填提問（100 字內），確認後前端帶 Idempotency-Key（即報告 id）送出
2. 後端驗證系統選擇與提問長度（超過 100 字回 400），並讀取每個系統所需的資料；缺資料回 422 且不扣點 〔NFR-001, NFR-031〕
3. 兩個以上系統時，規則把各系統放進同一套特質本體找出跨系統洞見作為 AI 的輸入素材；找不到任何洞見回 422（NO_INSIGHTS）且不扣點
4. 後端驗證點數足夠與生成次數上限，並確保每個系統的單維度報告已保存（相同的重用，不複製） 〔NFR-030〕
5. 後端以冪等方式扣點（一個系統 1 點；多個系統為各系統基本價之和 × 1.2 捨去、上限 30），建立生成中的 AI 報告（含 sources、提問與已列好的事實攤開），回 202 與報告 id 〔NFR-017, NFR-030〕
6. 背景以今天的日期、各來源報告的事實與面向、洞見候選與提問組成輸入，呼叫 AI；提問以資料而非指令交給 AI 〔NFR-031〕
7. 後端檢查輸出的章節順序、條列數量、字眼與引用；通過後把導師的各段附加到報告並標為完成 〔NFR-032〕
8. 前端導向「分析紀錄」，使用者看到報告生成中並於完成後閱讀（見 UC-055）

**Alternate Flows**

- **訪客嘗試取得**：拒絕並引導登入
- **點數不足**：回 402 並引導購點，不扣點、不呼叫 AI
- **選取的系統為空、重複或含不支援的系統，或提問過長**：回 400，不扣點
- **超過每小時或每日的生成次數上限**：回 429，不扣點
- **AI 生成失敗、逾時或輸出未通過品質檢查**：同一交易內標為失敗、記下原因並退回所扣點數，報告保留供再問一次 〔NFR-032〕
- **提問要求 AI 忽略規則、診斷或預測確切事件**：該部分不被回應；輸出仍須通過品質檢查，否則視為失敗並退點 〔NFR-031, NFR-032〕
- **相同 Idempotency-Key 重複請求**：只回報目前狀態，不重複扣點、不重複生成 〔NFR-017〕

**Postconditions**

- aiReports 有一筆報告（完成，或失敗且點數已退）；來源單維度快照不變；再問一次會新增一份而不覆蓋

> 備註：取代 UC-049 與 UC-050；自我分析納入可選系統見 UC-046

## UC-055 閱讀分析紀錄與 AI 報告

- **Actor**：CTX-ACTOR-002
- **對應 Story**：STORY-055
- **對應 Requirement**：FR-087, FR-088

**Preconditions**

- 使用者已登入

**Main Flow**

1. 使用者從 header 的「分析紀錄」進入，系統回傳本人未到期的 AI 報告卡片（新到舊、最多 100 筆，不含報告內容），顯示時間、來源位置結論、提問與狀態
2. 有生成中的報告時，前端定期重新讀取，完成或失敗後刷新點數
3. 使用者點「查看報告」，系統回傳該報告全文；報告頁依骨架顯示分析概要、事實攤開、值得注意的點、共同的優勢與劣勢、過去現在未來的垂直時間線、回應提問與結論 〔NFR-003〕
4. 讀取不呼叫 AI、不扣點、不重新計算

**Alternate Flows**

- **訪客開啟分析紀錄**：只顯示登入提示，不導回首頁
- **報告生成中**：報告頁顯示進度與已列好的事實，完成後自動更新
- **報告失敗**：顯示已退點與失敗原因，可帶原系統與原問題「再問一次」
- **生成中的報告超過逾時門檻仍無結果**：讀取時標為失敗並退點（工作程序已消失） 〔NFR-032〕
- **報告屬於他人、不存在或已到期**：回傳找不到，不洩漏存在與否 〔NFR-003〕
- **還沒有任何報告**：顯示說明與建立入口

**Postconditions**

- 報告內容不變；不產生新的扣點

## UC-056 從單維度報告進入深入分析

- **Actor**：CTX-ACTOR-002
- **對應 Story**：STORY-056
- **對應 Requirement**：FR-085, FR-087

**Preconditions**

- 使用者開啟某個穩定特質系統的單維度報告（塔羅、盧恩與星座運勢沒有此入口）

**Main Flow**

1. 報告最後顯示「深入分析」入口（一個系統 1 點起）
2. 使用者點入口，進入「綜合分析」表單，該系統已預選，可加選其他系統與填寫提問
3. 後續依 UC-054

**Alternate Flows**

- **訪客**：入口顯示為登入，不進入表單
- **預選的系統使用者尚未備齊資料**：該系統在表單中無法選取並顯示需要什麼

**Postconditions**

- 未建立任何報告，直到使用者送出
