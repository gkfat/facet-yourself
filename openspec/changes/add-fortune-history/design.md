## Context

塔羅與盧恩的紀錄在 `users/{uid}/tarotDraws/{YYYY-MM-DD}`、`runeDraws/{YYYY-MM-DD}`（文件 id 為台北日期，一天一筆）；卦象將在 `hexagramDraws/{YYYY-MM-DD}_{seq}`（一天可多筆，見 `add-hexagram-divination`）。各 service（`TarotService`、`RuneService`）已有「紀錄 → 回應（含固定內容）」的轉換 `toResponse`，目前只用於今天。今日運勢頁（`app/pages/fortune.vue`）以 URL hash（`#tarot`、`#rune`…）決定開哪個面板。

固定內容沒有「依金鑰讀取」的通用 API（塔羅、盧恩的內容只隨各自的每日 API 回傳），所以歷史 API 必須自己帶出內容。

## Goals / Non-Goals

**Goals:**
- 已登入使用者能回看最近 3 個月的塔羅、盧恩、卦象結果，並看到完整內容。
- 只讀、不新增資料；查詢量有明確上限。
- 重用既有的紀錄轉回應邏輯，不複製內容組裝。

**Non-Goals:**
- 不做瑪雅 Kin、星座運勢的歷史（Kin 可由日期重算、星座運勢不儲存，皆留待後續）。
- 不做統計、趨勢、元素或牌面分布，不做搜尋、篩選、分享、匯出。
- 不改抽取、扣點、保存期限；不新增集合、索引或欄位。

## Decisions

1. **時間窗口固定最近 3 個月，不依賴實際保存狀態。**
   常數 `FORTUNE_HISTORY_MONTHS = 3`，起點為 `addMonths(now, -3)` 換算成台北日期。即使舊的塔羅盧恩紀錄因沒有 `expiresAt` 而仍存在，也不顯示窗口外的資料；窗口也使每次讀取有上限。
   - 替代方案：顯示所有仍存在的紀錄。結果會隨保存政策的變動而變，且舊的永久紀錄可能很大，故不採用。

2. **查詢方式：每個來源以「文件 id 範圍」查窗口內的紀錄，再在記憶體中依日期分頁。**
   - 塔羅、盧恩：文件 id 在 `[起始日, 今天]` 之間，最多約 92 筆各一。
   - 卦象：文件 id 介於 `起始日_` 與 `今天_`，以 1000 筆為上限；若達上限，在日誌記警告並於回應標示 `truncated: true`（不靜默截斷）。
   - 不需複合索引，不新增索引。

3. **分頁以「有紀錄的日期」為單位：一次最多 14 天，游標為 `before` 日期。**
   先只用文件 id（不讀內容）算出窗口內有紀錄的日期集合，由新到舊切出本頁的 14 個日期，再只為這些日期的紀錄載入內容。回應含 `nextBefore`（本頁最舊日期；沒有更多時為 null）。沒有任何紀錄的日期不出現。
   - 為什麼不一次回傳全部：每筆都帶固定內容，3 個月 × 3 項可達數百筆，分頁讓單次回應小而可預期。

4. **內容由各 service 的唯讀方法提供：`listRange(uid, fromDate, toDate)`。**
   每個 service 新增一個只讀方法，回傳該區間內的 `{ date, record, content }`，轉換重用既有 `toResponse`；`FortuneHistoryService` 只負責合併三個來源、依日期分組、切頁。不改 `DailyDrawEngine`，也不改抽取路徑。
   - 內容缺少（例如某筆固定內容已被撤下）：該項回 `content: null` 並在日誌記一筆警告，不讓整頁失敗，也不隱藏該筆紀錄。

5. **API：`GET /api/fortune/history?before=YYYY-MM-DD&limit=14`。**
   - 需登入（沿用預設的 `required`，訪客得 401）；`before` 選填，須為合法台北日期且不晚於今天、不早於窗口起點；`limit` 預設與上限皆 14，超過回驗證錯誤。
   - 回應 `{ days: [{ date, tarot: Item | null, rune: Item | null, hexagrams: Item[] }], nextBefore, truncated }`，經 response schema `parse`；`Cache-Control: private, no-store`。
   - 日期、身分一律由伺服器決定；`before` 只是游標，不影響誰的資料。

6. **前端：今日運勢頁加「歷史」入口與 `#history` 面板。**
   `FortuneView` 加 `'history'`，入口不是抽取卡片，放在入口格的上方或旁邊（一個「歷史運勢」按鈕），以免混入每日卡片的版型。`HistoryPanel.vue` 以日期分組由新到舊，每天一張卡，列出當天各項（牌名與方位、符文與方位、卦名與動爻、第幾卦），展開看完整內容；底部「載入更多」。重用既有面板的展示元件（牌面、符石、六爻圖）而不重寫。訪客點入口只看到登入提示，不呼叫 API；沒有紀錄時顯示空狀態並引導回今天的入口。
   - 卦象項目依 `HEXAGRAM_ENTRY_ENABLED`：關閉時 API 不含卦象，畫面不顯示。

7. **不寫任何資料。** 歷史是純讀取，不更新「已讀」、不寫日誌內容（只記筆數與是否截斷，不記結果內容）。

## Risks / Trade-offs

- [塔羅盧恩仍有 3 個月以前、沒有 `expiresAt` 的舊紀錄] → 窗口固定 3 個月，舊紀錄不會出現在歷史。
- [卦象一天大量加卦使讀取變大] → 1000 筆上限與 `truncated` 標示，並分頁；實務上受點數限制。
- [內容載入造成讀取成本] → 只為本頁 14 天載入內容；固定內容讀取走既有的 `FixedContentService`（有既有快取）。
- [歷史功能暴露「刪除」的期待] → 第一版不提供單筆刪除；刪除帳號與保存期限到期仍沿用現行行為。
- [星座運勢與 Kin 缺席讓「運勢流動」不完整] → 明確標為第一版範圍；後續可由日期重算 Kin、星座運勢另案。
- [卦象 change 與本 change 的合併順序] → 卦象尚未實作時，卦象區段不輸出；兩者無程式碼重疊（本 change 只新增檔案與一處 hash 路由）。

## Migration Plan

無資料遷移。部署即生效；回滾為移除入口與 API，不影響任何資料。
